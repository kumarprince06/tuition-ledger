# ADR-0015 Calendar: iCal feeds and WhatsApp nudges first, Google OAuth sync later
**Context.** Teachers want sessions in the calendar they already use, and the product wants attendance marked on time. Google Calendar write access and free/busy are "sensitive" OAuth scopes: above 100 users Google requires an app verification review that takes weeks and a privacy-policy audit, which would put the pilot at risk.
**Decision.** MVP ships (1) a per-user iCal subscription feed with a signed, revocable token and a deep link to the attendance screen in every event, and (2) a WhatsApp nudge to the teacher before each session with the same link. Google two-way sync and free/busy conflict checks are a Standard-plan feature after the pilot; verification is started in sprint 3 so it is ready by sprint 6.
**Consequences.** Every teacher gets a real calendar on day one with no OAuth and on any calendar app; attendance gets easier through the nudge, which is where the time is actually saved. A calendar can never record who attended; marking stays an explicit action in our system. Feed tokens are personal data access tokens and are treated like refresh tokens (hashed, revocable, rotated on request).
**Alternatives.** OAuth first: blocked by verification timing. Reading attendance from calendar acceptance: wrong by design.
